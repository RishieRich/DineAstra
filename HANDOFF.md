## 1. What this is

**DineAstra** (originally scaffolded under the internal name *Darpan*, with
the code, the API and the demo credentials) is a daily operating briefing for
a hotel/restaurant general manager. The product claim it is built around:

> Every figure on the screen can be traced to the record it came from, and a
> model is never asked for a number.

It runs end to end on generated sample data with **no API keys**. With a key,
a model writes the prose; the figures are computed either way, and an answer
whose numbers do not match what was computed is discarded before it reaches
the screen.

## 2. Run it

Two terminals, repository root. Nothing to configure.

```bash
# backend
.venv/Scripts/python -m uvicorn ui.backend.main:app --port 8000

# frontend
cd ui/frontend && npm run dev
```

http://localhost:5173 — sign in `owner@dineastra.demo` / `dineastra`
(the login card also has a "continue instantly" demo button).

First time on a new machine:

```bash
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
cd ui/frontend && npm install
```

Tests: `.venv/Scripts/python -m pytest tests/ -q` → **26 passing**.

`DEMO.md` has the six-step demo script with the exact clicks and figures.

## 6. Decisions worth knowing before you change something

- **Only prose is canned, never figures.** `mock_bank.py` templates carry
  `{placeholders}` and no digits — `audit_templates()` enforces it. That is
  what makes the no-keys demo honest.
- **The guard runs before the first token in live mode.** A guard cannot
  un-say a word already on screen, so the model's text is collected, checked,
  then streamed. You lose true model-streaming latency; you gain the guarantee.
- **Routing is rule-based, not model-based.** So an unsupported question
  refuses with no model call, and the same question routes identically every
  demo.
- **Daily metrics compare like-for-like day types** (a Monday against other
  Mondays). On a Mon–Thu-heavy property a blended 30-day mean reports the
  shape of the week as a movement.
- **Per-segment margin floors** (corporate 60 / MICE 48 / wedding 42 / social
  40). A single house floor made every non-corporate event flag, burying the
  one real signal.
- **Startup model validation goes beyond listing ids.** Gemini lists models
  that then answer "no longer available to new users", so validation also
  makes one minimal generation. A transient 429/503 counts as valid-but-busy.
- **Secrets never reach a log or a trace.** Gemini passes its key in the URL,
  so provider error text is scrubbed and httpx request logging is quietened.
  See §8.

## 8. Risks and gotchas

- **Rotate the Gemini API key.** While testing live mode I found that Gemini
  passes its key as a URL query parameter, and both httpx's INFO request log
  and the text of an `HTTPStatusError` carry that URL — a real key was written
  to `data/runtime/traces.jsonl` and the server log before I caught it. I
  scrubbed the code paths and redacted the written file, and `data/runtime/`
  was git-ignored throughout so **nothing was committed**. But the key did
  touch local disk. It is still in the shell environment.
- **The free-tier Gemini key is heavily rate-limited.** Expect 429/503 on
  `gemini-flash-latest`. The fallback is correct — figures stay right and the
  checked template is served — but if you want model prose in a live demo,
  test immediately beforehand. `DARPAN_PROVIDER=mock` forces the reliable path.
- **Windows:** use `PYTHONIOENCODING=utf-8` when a script prints `₹` to a
  console, or it raises `UnicodeEncodeError`.
- **The name is split.** Product/UI says DineAstra; the API, package names,
  env vars (`DARPAN_SECRET`, `DARPAN_PROVIDER`) and the demo login still say
  Darpan. Deliberate to leave, but pick one before anything external sees it.
